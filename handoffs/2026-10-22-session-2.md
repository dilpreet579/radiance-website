## What was wrong (scanner camera)

`html5-qrcode` overwrites `#reader`'s inline style with `position: relative`. That removed our `absolute inset-0`, so `#reader` measured 0x0 and the `<video>` got `width: 0px`. The stream was running (`videoWidth` 480, playing) but nothing was visible. Fix: `#reader` is now `h-full w-full` inside an `absolute inset-0` wrapper that carries the `hidden` toggle and the `[&_video]` rules. Do not put sizing classes on `#reader` itself.

Also fixed: cleanup used to call `stop` before `start` resolved (StrictMode, fast Stop tap), leaking the stream. Cleanup now chains off the start promise. The catch no longer hides the cause; the banner shows `e.name` (e.g. `NotAllowedError`).

## Gotchas

- Camera needs HTTPS or localhost; on first use Chrome shows a site permission prompt (I tapped "Allow this time" on the user's phone).
- `adb shell am start -a VIEW ...` opened Samsung Internet; use `-n com.android.chrome/com.google.android.apps.chrome.Main` so Chrome (the only one exposing the DevTools socket) gets it. Bridge: `adb forward tcp:9222 localabstract:chrome_devtools_remote`, then `/json/list` + a WebSocket (Node's global `WebSocket` works; no extra deps). Scripts used lived in the session scratchpad, not in the repo.
