## Ticket + reminder emails (`lib/email.ts`, `lib/ticket-image.tsx`, `lib/reminders.ts`)

- **Ticket email = exact on-screen ticket as a PNG.** CSS in email can't match the site (no web fonts, no positioned notches, no background images), so `renderTicketPng()` draws the `TicketView` design with `next/og` (satori + resvg) at 2x and `sendTicket` attaches it inline (`cid:ticket`, also a downloadable attachment). No public ticket URL (tokens are sequential, so a public image URL would leak names). If the render throws, it logs "ticket image render failed" and sends the older HTML ticket instead. Token ID is also in plain text under the image.
- Satori gotchas learned the hard way: (1) images inside an `overflow: hidden` ancestor draw blank or clipped, so the card has no `overflow:hidden` and the header/footer carry their own rounded corners, and notches are half-discs inside the card edge; (2) transparent/palette PNGs misdraw, so the logo, QR and sponsor logo are flattened onto their background colour via sharp; (3) `<img>` needs explicit width and height; (4) every flex child needs `display: flex`.
- Fonts (Bricolage 800, DM Mono 400/500, Hanken 400/600/700 as static TTFs) and `ticket-pattern.jpg` live in `assets/`, loaded with `fs` at runtime. `next.config.ts` has `outputFileTracingIncludes` for `/register` so Vercel ships them (verified in the build's `.nft.json`). If the ticket image render ever fails on Vercel, look there first.
- **Reminder emails** now match: maroon page, logo, gold date label, event heading, venue, the admin-written body (still `{name} {token} {venue} {event}` templates), a cream card with that student's QR (generated per recipient, inline `cid:qr`) and token, sponsor strip. `renderReminder` is async and returns `attachments`; `sendDay` and `sendTest` pass them. The heading repeats the event and venue the seeded body also states; shorten the seeded bodies if that reads as repetition.
- `public/email-logo.png` (864 px) is loaded by URL from `NEXT_PUBLIC_SITE_URL` in the reminder emails, so it only shows once deployed and that variable is the live domain.

## What was wrong (scanner camera)

`html5-qrcode` overwrites `#reader`'s inline style with `position: relative`. That removed our `absolute inset-0`, so `#reader` measured 0x0 and the `<video>` got `width: 0px`. The stream was running (`videoWidth` 480, playing) but nothing was visible. Fix: `#reader` is now `h-full w-full` inside an `absolute inset-0` wrapper that carries the `hidden` toggle and the `[&_video]` rules. Do not put sizing classes on `#reader` itself.

Also fixed: cleanup used to call `stop` before `start` resolved (StrictMode, fast Stop tap), leaking the stream. Cleanup now chains off the start promise. The catch no longer hides the cause; the banner shows `e.name` (e.g. `NotAllowedError`).
